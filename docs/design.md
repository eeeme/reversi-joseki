# 定石帳（リバーシ版）設計書

## 0. 前提と方針
- 将棋版「定跡帳」と同じ考え方・同じ見た目（暗い背景の「静かな鍛錬」テーマ）・同じ操作感で作る。
- 無料・広告なし。応援（1回きり3種と毎月）だけを持つ。データはすべて端末内に保存し、外には送らない。
- 将棋版で外したもの（解析エンジン、評価値、局面の共有、詰将棋のような問題集）は、リバーシ版でも入れない。
- **名前に「オセロ」は使わない。** 「オセロ」はメガハウスの登録商標なので、アプリ名・ストア掲載文・アイコンの文字には入れず、すべて「リバーシ」と書く。説明文で「オセロ」を検索語として使うのも避ける。

| 区分 | 内容 |

## 3. ルールと盤（`src/reversi/core.ts`）

### 3-1. 盤の持ち方
- 64マスの配列。0＝空、1＝黒、2＝白。マスの番号は `a1=0 … h8=63`（列 a〜h、行 1〜8）。
- 局面＝盤64マス＋手番（黒/白）。
- 初期配置は d4=白、e5=白、d5=黒、e4=黒。黒が先に打つ。

### 3-2. 処理
- `legalMoves(pos)`：8方向に挟めるマスを合法手として返す。
- `applyMove(pos, sq)`：石を置いて挟んだ石を返し、手番を交代する。
- パス：合法手がなければ自動でパスして手番を交代する。両者とも打てなければ終局。
- 終局時は石数を数えて勝敗を出す（表示のみ。評価値は出さない）。

### 3-3. 局面の文字表現（将棋版の SFEN の代わり）
- `'-'`（空）・`'X'`（黒）・`'O'`（白）の64文字に、手番の1文字を足した65文字で表す。例：`---------------------------OX------XO---------------------------X`
- 局面検索、合流（手順前後）の判定、次の手の集計は、すべてこの文字列で比べる。

### 3-4. 対称形の正規化（リバーシで一番大事な追加点）
- 初期局面は対称なので、黒の初手 f5・d3・c4・e6 の4つは、盤を回転・反転すれば同じ局面になる。
- 取り込んだ棋譜や指した手は、**初手が f5 になるように盤全体を変換して保存する**（8通りの対称変換のどれかを当てる）。
- 表示も f5 始まりにそろえる。設定で「打った向きのまま表示」に切り替えられるようにする。
- 合流と局面検索では、8つの対称形のうち文字列が一番小さいものを代表として比べる。そうすると、向きの違う同じ局面も一致として扱える。

## 4. 表記・棋譜（`src/reversi/notation.ts`, `src/reversi/kifu.ts`）

### 4-1. 1手の表記
- 座標そのまま（`f5`、`d6`）。画面では大文字（`F5`）も受け付ける。
- パスは `pass`（画面では「パス」）。
- ツリーの各枠には「● F5」「○ D6」のように手番の色を付ける。

### 4-2. 取り込める形式

| 形式 | 例・内容 | 対応 |
|---|---|---|
| 棋譜文字列 | `f5d6c3d3c4f4f6...`（大文字・空白・改行が混ざってもよい） | 最優先。オセロクエストや eOthello などからのコピーはほぼこの形 |
| GGF | `(;GM[Othello]PB[...]PW[...]BO[8 ...]B[f5]W[d6]...;)` | 対局者・結果・途中局面からの開始も読む |
| 変化付きテキスト | 1行1手順の複数行（`f5d6c3...` を行ごとに） | 複数の手順を1冊にまとめて取り込む |
| 盤面図 | 8行の `X / O / -` ＋手番 | 盤面からの開始 |

- 取り込み時に正規化（3-4）と、重複している手のまとめ（将棋版の mergeImport と同じ）を行う。
- 書き出しは「棋譜文字列（本線）」と「全変化を1行ずつ」の2種類を、コピーで出す（将棋版と同じく、ファイルのダウンロードは使わない）。

### 4-3. 実戦照合
自分の対局の棋譜文字列を貼ると、正規化してから「何手目で定石を外れたか」「定石では何を打つか」を表示する。将棋版と同じ機能。

## 5. 定石の名前（新機能）
- 有名な定石（兎・虎・牛・鼠・猫・蛇・羊・快速・ローズ・バッファロー・Fシャープ など）の手順と名前の対応表を、アプリに入れておく。
- ツリーの枠と閲覧画面の見出しに、その局面で成立している定石名を小さく表示する（例：「F5 D6 C3 D3 C4 → 虎」）。
- 名前と手順は一般に広く知られている事実だけを使い、特定の本やサイトの文章は写さない。表は自分で手入力して作る。
- 最初に入れるサンプル本は「主要定石（兎・虎・牛の基本形）」1冊にする。

## 6. 画面（将棋版との差分だけ）

### 6-1. 盤（`Board.tsx`）
- 8×8、緑ではなく、テーマに合わせた暗い盤面（細い線）に、黒石と白石。直前の手には小さな印を付ける。
- 打てるマスに薄い点を出す（設定でオフにできる）。
- 盤の上に「● 黒 12　○ 白 9」の石数。
- 閲覧中は、盤の右半分のタップで本線を1手進め、左半分のタップで1手戻る（将棋版と同じ）。
- 盤の高さは手を進めても変えない（将棋版で直した「盤がずれない」をそのまま守る）。

### 6-2. 閲覧
- 下段は将棋版と同じ並び：⏮ ◀ 現在手 ▶ ⏭、その下に検索・しおり・コピー・編集（鉛筆）・反転（↑↓）。
- 「次の手」は横スクロールの一列。各手に出現率・局数・勝率（2局以上のときだけ）を出す。
- パスの局面では「パス」のボタンを1つだけ出す。

### 6-3. 盤面編集
- 石を置くたびに、黒→白→空 と切り替える。駒箱はない。
- 手番を選び、「作成」で新しい本にする（将棋版と同じく、確認画面で手番と名前を入れる）。
- 局面検索用にも同じ画面を使う。

### 6-4. 練習・今日の復習
- 将棋版と同じ。自分の色（黒/白）を選ぶと、相手の手は自動で打たれ、自分の番で定石の手を打って答える。
- 分岐があれば、どれを打っても正解。正解・不正解は大きな◯／✕、変化を最後まで打ち切ったら「完」を出す。
- 今日の復習は「今日の復習に使う」をオンにしたフォルダだけが対象。復習日が来た局面から最後まで通して出題する。

### 6-5. ツリー
- 将棋版と同じ。手数は下へ、変化は右の列へ枝分かれ。2本指を使わず1本指で縦横に動かせて、慣性も付ける。
- 定石名がある枠には小さな印を付ける。

## 7. 局面検索の似ている度合い
- 64マスのうち、両方で同じ色の石があるマスの数を「両方で石があるマスの数」で割った値（将棋版の Jaccard に近い考え方）。
- 8つの対称形すべてで計算して、一番高い値を使う。
- 完全一致（正規化した文字列が同じ）を先に並べ、次に似ている順で縮小盤面付きで出す。

## 8. データ構造（将棋版とほぼ同じ）

```
Book {
  id, name, folderId?, tags?, meta?: { black?, white?, date?, event?, result? },
  bookmarks?: nodeId[],
  rootPos: string        // 65文字の局面（初期配置なら標準形）
  rootId, nodes: Record<id, Node>,
  srs: Record<nodeId, { due, interval, ease, reps }>,
  createdAt, updatedAt
}
Node { id, parent?, move?: 'f5' | 'pass', children: id[], comment? }   // children[0] が本線
Folder { id, name, review?, createdAt }
```

- IndexedDB のストアは `books` と `folders`（将棋版と同じ）。データベース名は `reversi-joseki` に変える。
- 勝敗（result）は石数（例：`黒 36 - 28`）でも持てるようにする。次の手の勝率計算では「黒勝ち・白勝ち・引き分け」に直して使う。

## 9. 間隔反復・応援・Android
- 間隔反復：将棋版の SM-2 簡易版をそのまま使う（初回1日 → 3日 → 前回の間隔×ease、間違えたら10分後）。
- 応援：将棋版と同じ構成。アイテム ID は将棋版と同じ名前（`support_small` / `support_medium` / `support_large` / `support_monthly`）でよい。アプリごとに別物として作ることになるので、ぶつからない。
- X 投稿のハッシュタグは `#定石帳アプリ`。
- Android：Capacitor、署名鍵は**新しく作る**（将棋版の鍵は使い回さない）。CI の作り方は将棋版と同じ。

## 10. ストア掲載の注意
- カテゴリは「ボードゲーム」。
- 説明文は「リバーシ（白黒の石を挟んで返すゲーム）の定石を…」の形で書く。「オセロ」と書かない。
- スクリーンショットにも「オセロ」の文字が写らないようにする（サンプル本の名前なども含めて）。
